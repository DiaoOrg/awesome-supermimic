# Jev curation / Jev 推荐评分

The README ranks **reading and reuse priority**, not scientific validity, training speed or benchmark performance. The same score orders projects within each purpose category and selects the global Top 10. GitHub Stars remain visible only as repository metadata.

README 中的分数衡量**阅读与复用优先级**，不是研究质量认证、训练速度榜或统一性能评测。分类内排序与前十总表使用同一分数，GitHub Star 仅作为仓库信息展示。

## Snapshot / 本次快照

- **Date / 日期:** 2026-10-30.
- **Model / 模型:** TypeSafe `jev-1.14.0`, pinned rather than a moving alias.
- **Coverage / 覆盖:** all 38 accessible community projects; 38 actual API calls, each with one Score and one independent recommendation Choice.
- **Evidence / 证据:** frozen English project summaries from the reviewed README, including contributions, reported outcomes and limitations; pinned upstream links accompany every profile. InstinctMJ was refreshed to `03563ee` before scoring. The other 37 source revisions matched their reviewed branch heads in the preceding freshness audit.
- **Outcome / 输出:** 10 overview entries, 15 projects marked ⭐.
- **API-reported usage / API 返回用量:** 40,119 input tokens, 1,733 output tokens.

## Rules / 规则

The rubric was fixed before the calls. Jev receives one evidence profile per call, with the same task and criteria. Project title, owner, source URL, GitHub Stars and previous recommendation markers are not supplied as metadata to the model. Implementation and dependency names occurring naturally in the evidence remain, so this is not a guarantee of complete anonymization.

规则在调用前固定。每次只发送一份项目证据和同一套评判标准；不发送项目标题、作者、来源 URL、GitHub Star 或旧推荐标记这些元数据。证据中自然出现的实现与依赖名称仍保留，因此不能视为完全匿名评审。

**Priority Score:** Jev evaluates direct SuperMimic relevance, substantive contribution, reusable workflows/artifacts and documented evaluation or diagnostic evidence against five descriptive levels: little demonstrated value, limited value, useful focused reference, strong starting point, outstanding evidence-backed reference. Controlled comparisons and honest negative results can add value. Hardware scale, dataset size or a large raw metric alone do not establish merit. Exact wording is in [rubric.json](2026-10-30/rubric.json).

**优先级分数：** Jev 根据与 SuperMimic 的直接关系、贡献、可复用流程/产物，以及评测或诊断证据，在五档描述性等级上评分；消融和诚实的负结果也可以体现价值，不能单凭显卡规模、数据量或某个大数字得高分。完整规则见上方 JSON。

The API Score is on a 0–4 scale. Displayed points = Score × 25, rounded to one decimal. Sorting uses the unrounded Score; exact ties use case-insensitive owner/repository order. The first ten become the overview; every detailed category uses the same ordering. Close scores are not evidence of a meaningful quality difference.

API 分数范围为 0–4，展示时乘以 25 并保留一位小数；排序使用原始分数，同分按 owner/repository 排序。总榜取前十，分类内使用相同顺序。相近分数不能解读成显著质量差距。

**Recommendation Choice:** a separate question selects `star` or `list_only`. It asks whether a distinctive, useful reason to study or reuse this work is supported by adequate evidence or artifacts. There is no Top 10 quota and no score threshold for ⭐. The returned Choice is applied directly, without manually promoting or demoting projects.

**推荐标记：** 另一个独立问题在 `star` 与 `list_only` 中选择，判断是否存在证据或产物支持的独特阅读/复用价值。⭐ 不限前十，也不设分数门槛，直接采用返回的 Choice，不人工改名单。

Jev judged **human/agent-prepared summaries**, not an independent reading of every repository or a rerun of experiments. Summary coverage and wording affect results. This is a single inference snapshot; stability across reruns and calibration for robotics curation have not been established. Confidence describes the output distribution, not the probability that a project is good or its claims are true. Quantitative highlights are source-based editorial summaries, not text generated by Jev.

Jev 判断的是**经整理的证据简介**，并没有独立通读每个仓库或重跑实验。输入覆盖度与措辞会影响结果；本次只有一轮推理，尚未验证重跑稳定性或机器人项目推荐的校准性。confidence 表示输出分布集中程度，不代表项目优秀或结论正确的概率。表格中的量化亮点由来源证据整理，不是 Jev 生成的文字。

For a refresh, update the source evidence first and evaluate all projects with the same frozen rubric and pinned model. Preserve complete responses and failures; do not silently substitute manually invented scores or rerun selectively to obtain preferred winners. A model/rubric change starts a new snapshot.

后续更新先核对上游证据，再用相同固定模型与规则评估全部项目，保留完整返回和失败记录；不能编造分数或只重跑个别项目以得到偏好的名次。更换模型或规则应建立新快照。
